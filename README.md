# 浮世勤怠帖（うきよきんたいちょう）

和紙に墨、朱をひと差し。浮世絵の佇まいでつくった、**個人用の勤怠アプリ**です。

- 出勤・退勤をスマホで打刻（押し忘れても既定の時刻で入ります）
- 遅刻・早退・欠勤・有休を登録し、**自社宛て・現場先宛てのメール**をそのまま作成
- 毎日の退勤時に **Teams のチャネルへ1日1回の投稿**（文面を確かめてから送信）
- 暦（カレンダー）で過去の日を修正
- 月のまとめ（出勤日数・合計勤務・残業）と残業の注意
- 月末に **会社の Excel と同じ列**で書き出し（貼り付けるだけ）

記録と設定は**使う人のスマホの中（ブラウザ）にだけ**保存されます。サーバーはありません。

---

## 使い始める（自分用に動かす手順）

このリポジトリを自分用に複製して、GitHub Pages で公開するだけで使えます。費用はかかりません。

1. **複製する**：このページ右上の「Fork」→「Create fork」
2. **公開する**：複製したリポジトリで「Settings」→ 左の「Pages」→
   「Build and deployment」の Source を **Deploy from a branch**、Branch を **main / (root)** にして「Save」
3. 1〜2分待つと `https://あなたのユーザー名.github.io/ukiyo-kintai/` が開けるようになります
4. **スマホで開いてホーム画面に追加**
   - iPhone（Safari）：共有ボタン →「ホーム画面に追加」
   - Android（Chrome）：メニュー →「ホーム画面に追加」／「アプリをインストール」
5. アプリの **設定**（ホームかまとめの右上、短冊の左の歯車）で、氏名・部署・宛先などを入れます

> 公開されるのはアプリのプログラムだけです。氏名・メールアドレス・Teams の URL・勤怠の記録はプログラムに含まれず、各自のスマホの中にだけ保存されます。

## 設定する項目

| 項目 | 使われるところ |
| --- | --- |
| 姓・氏名 | メールの件名と本文 |
| 自社での部署 | 自社宛てメールの本文 |
| 現場での所属 | 現場先宛てメールの件名と本文 |
| 自社宛て／現場先宛てのメール | 連絡メールの宛先 |
| 自分のメール | 月末の書き出しを自分に送るとき |
| Teams のワークフロー URL | 毎日の投稿、欠勤・有休の投稿 |
| 返信先スレッドのリンク（毎月） | 投稿を返信する先のスレッド |
| 始業・終業・休憩 | 押し忘れたときの既定、残業の計算（所定＝終業−始業−休憩） |
| 作業内容（作業場所）の初期値 | 書き出しの「作業内容」列 |
| 残業の上限 | 残業注意の画面 |
| 使い始めた日 | この日より前の打刻のない日は空欄のまま |

## Teams のワークフローを作る（毎月のスレッドに返信する）

毎月だれかが立てるスレッド（例：「2026年 11月度／庄司」）に、`10/28 18:30 業務終了` のような返信を送ります。ワークフローは一度作れば、月が変わっても作り直す必要はありません。

### 1. 受け口を作る

1. Teams で、スレッドがあるチャネルの「…」→「ワークフロー」
2. 「**Webhook アラートをチャネルに送信する**」（Send webhook alerts to a channel）を選ぶ
   ※「特定のユーザーから」「組織内のユーザーから」はサインインが必要なため、このアプリからは使えません
3. 名前（例：勤怠連絡）、チーム、チャネルを選んで保存する

### 2. 「返信する」に入れ替える

1. 「ワークフローのホーム」→ 作ったワークフローを開いて「編集」
2. 「Teams webhook 要求を受信したとき」の**下にある手順（カードを投稿する手順など）を削除**する
3. 「＋」→ Microsoft Teams の「**チャネル内のメッセージで返信する**」（Reply with a message in a channel）を追加する
   - 投稿者：**フロー ボット**
   - 投稿先：**Channel**
   - チーム・チャネル：スレッドがあるチーム・チャネル
   - メッセージ ID：式で `triggerBody()?['messageId']`
   - メッセージ：式で `triggerBody()?['html']`
4. 保存する。「Teams webhook 要求を受信したとき」を開くと出ている **URL をコピー**する

### 3. アプリに入れる

1. 設定「Teams のワークフロー URL」に、コピーした URL を貼る
2. 設定「**返信先スレッドのリンク（毎月）**」に、今月のスレッドの「…」→「**リンクをコピー**」で取ったリンクを貼る
3. 「**テストを1通送る**」で、スレッドに返信が付くか確かめる

月が変わると、ホームに「今月のスレッドのリンクを設定に貼ってください」と出ます。新しいスレッドのリンクに貼り替えるだけで続けて使えます。

アプリが送る中身（JSON）：`text`（本文）、`html`（改行を `<br>` にした本文）、`messageId`（返信先の投稿）、`channelId`、`teamId`。チャネルに新しく投稿するひな形のままでも使えるよう、Adaptive Card も一緒に送っています。

> URL を知っている人は誰でもそのチャネルに投稿できます。人に見せたり、リポジトリに書き込んだりしないでください。
> 会社の環境によってはブラウザから送れないことがあります。そのときは「送信しました。届いたか確かめてください」と表示されるので、チャネルを確認してください。

## メールについて

「自社に送る」「現場に送る」を押すと、宛先・件名・本文が入った状態で**メールアプリが開きます**。送信はメールアプリで行います。押さない限り、メールは送られません。送る前に「文面を直す」で件名と本文を直せます。

---

## 月末の書き出し

タブ「まとめ」→「月末の書き出しをする」。

- **Excel用に写す**：表の文字がコピーされます（列はタブ区切り）。PC の Excel で、その月の1日の「月日」のセルを選んで貼り付けます。
- **自分にメールで送る**：スマホから自分宛てに表を送り、PC で開いてコピー → 貼り付け。

列：`月日 / 勤怠区分 / 開始 / 終了 / 休憩 / 時間 / 作業内容（作業場所） / 備考`。土日祝と記録のない日は月日だけで、ほかは空欄です。

---

## バックアップ

記録はスマホのブラウザの中にあるため、**ブラウザのデータを消す・機種変更する**と消えます。
設定画面の「**記録を書き出す（ファイル）**」でときどき保存し、新しい端末では「**記録を読み込む**」で戻せます。

## ファイル構成

```
index.html             アプリ本体（画面・保存・文面・送信のすべて）
manifest.webmanifest   ホーム画面に追加するための情報
sw.js                  電波がなくても開けるようにするしくみ
icon-192.png, icon-512.png
img/                   挿絵（歌川国芳・河鍋暁斎ほか、パブリックドメインの作品より）
docs/spec.md           仕様メモ（文面の決まり・計算・書き出しの列など）
```

ビルドは不要です。`index.html` を書き換えて push すれば、GitHub Pages に反映されます。
手元で試すときは、このフォルダで `python3 -m http.server` を実行し、`http://localhost:8000` を開きます。

## 自分の会社に合わせて変える

メールの文面・件名・Teams の文面は `index.html` の `mailsFor()`・`teamsDaily()`・`teamsOff()` にまとまっています。決まりの詳細は [docs/spec.md](docs/spec.md) を見てください。

デザインはデザインシステム「浮世勤怠帖」（和紙・墨・朱の三色、筆文字・明朝・ゴシックの三書体）に沿っています。色や書体は `index.html` 冒頭の `:root` で変えられます。
